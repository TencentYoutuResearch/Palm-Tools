# Superagents 与 IM 操作指南

本文描述此 PR 的实现与使用方式。当前验收结果以 [验证说明](validation.md) 和 AC 对照（原始验收记录，见 validation.md） 为准，历史增量不代表当前全量检查通过。

## 创建一个长期团队

1. 切到 IM，打开“团队搭建助手”。在“新建团队草案”描述团队的目标，选择“保存目标并继续”。
2. 选择允许访问的工作区，按界面核对执行资源、账户绑定、能力信息及创建助手的预算和权限。默认资源推导有歧义时需要明确选择；保存目标本身不会启动执行。
3. 检查本次预留预算，明确是否允许在供应商真实额度未知时使用团队预算约束，确认启动创建助手。创建助手自身也受预算与权限控制。
4. 用普通语言说明期望结果、验收方式和需要找你决定的事项。助手可读取已选择且已授权的项目，通过问题核对需求。自然语言建议还不是已保存的配置或授权；按界面确认重要答案与方案。
5. 核对流程、项目绑定、验证命令、交付终点、角色资源、预算和授权。默认研发流程提供实现、独立评审和验证；其他已激活流程按自身声明运行。需要本机命令时，通过“配置本机验证命令”审阅并注册其执行定义，参阅 `verification-command-guide.md`。
6. 保存团队方案后，进入“团队管理”，选择“核对激活条件”。确认问题全部解决，再选择“确认激活此版本团队”。保存草案、助手说准备好了、已有旧激活回执都不等于当前运行条件有效。

同样的创建入口可继续创建其他团队，各自绑定工作区、资源和流程。长期联系人代表团队；底层运行会话不是联系人身份。

## 默认需求与缺陷流程

创建助手现在可读取随附的需求交付和缺陷修复模板，再按当前项目、资源、授权和命令配置生成待确认方案。模板只是方法建议，不能替代已登记配置或用户激活。

缺陷模板先在独立任务工作树中保存基线，再运行你登记的复现判断命令。该命令的成功必须表示确认了期望的缺陷；普通测试报错不会自动算复现通过。确认后再实现、独立评审和验证，评审和验证使用修复后的精确归档。

无法复现时，任务等待你明确处置。只有你针对当前基线和尝试确认的结构化豁免才能继续，系统会保留“未复现／已豁免”的事实。最终独立评审与验证仍必须执行；聊天中的“继续”不替代结构化决定。已有轻量或自定义流程按其已激活配置运行，Hub 不按任务名称硬编码这些阶段。

## 创建助手检查项目配置

创建助手可以检查选定工作区中的根文档、GitHub 工作流、GitLab CI、项目技能目录及插件清单。支持的技能目录为 `skills`、`.agents/skills`、`.codex/skills` 和 `.claude/skills`，读取各技能的 `SKILL.md`。

每条文件观察保留路径、内容哈希和时间。缺失位置会明确记录，超过扫描边界或无法安全读取的位置显示为覆盖不完整。待检查项与观察结果一同保存在草案中。检查结果用于方案取证。流程阶段可以绑定已登记的版本化 Skill/Plugin 指令资源。激活前核对来源、版本、内容哈希、执行 Host 及工具和权限要求，Worker 执行时使用冻结版本。项目中发现的技能文件需要经过资源登记和流程绑定。包含可执行程序的插件还需完成其安装配置。

## 提需求和查看结果

在联系人中选择团队，直接描述需求，例如“为这个接口增加分页，并保留现有调用兼容性”。不必手动点名 Worker，也不必每次重述开发流程。

团队按当前已激活并冻结到本次任务的配置执行。默认研发流程会产生不同的实现、评审和验证 Worker；缺少必要证据时 Hub 不会允许交付。返工和专家升级也必须符合已配置规则、预算和授权。

自动代码写入目前要求选定已提交过的 Git 仓库根目录。系统为每个任务创建独立工作树，不改动原工作区已有的未提交文件。同一任务的后续阶段和返工按已冻结的产物继续执行。Local 交付提供已验证归档和任务目录，明确标记为未合入；它不表示代码已经写回原工作区、提交或合并。

关联终态任务会保留原任务身份和拒绝反馈，新需求仍独立执行。本轮关联入口没有自动继承上次未合入归档的功能；需要继续使用旧代码时，应先明确代码来源和输入方案，不能仅凭关联关系推断已继承旧工作树。

打开“工作过程”查看阶段、分配、产物、评审、验证与需要你决定的事项。某个 Worker 的报告、某个阶段完成或一条聊天回复，均不单独证明整个需求交付。若交付策略要求人工验收，在相应结构化入口记录决定；聊天中的“通过”不会替代该记录。

IM 主联系人不列 Worker。排障时可切换到 Session；切换视图不启动新任务、不修改授权，也不停止正在执行的工作。任务的取消使用工作过程中的取消入口，并等待停止确认。

## 人工接管与恢复

在“工作过程”的任务详情中，选择“查看内部会话诊断”，可只读核对 Worker 的 Host、Session、Operation、租约 epoch、停止记录、结算与资源持有情况。它显示 Home 已留存的元数据，运行端存活状态另行标记为尚未探测。

需要人工处理工作区时，选择“暂停并接管”，填写原因并确认。任务先进入“接管待确认”。系统撤销当前执行租约，等待各 Worker 的真实停止与用量结算。界面显示“已暂停，可人工处理”后，才能将受管执行视为已经停止。远端未确认停止或用量待对账时会继续等待。

人工处理完成后，选择“恢复自动执行”并确认原因。当前版本采用所有阶段重新核验的策略，保留原任务身份与历史记录，清除当前已选证据和人工验收，并创建各阶段的新尝试。恢复仍需通过当前权限、预算、执行资源和证据准入。当前冻结的授权已变更或撤销时，恢复会被拒绝。

浏览器会先持久保存操作身份。响应丢失时，使用“恢复原操作请求”查询原收据。任务版本改变且 Home 证明原请求未提交时，需按当前任务重新决定。

本版本将人工操作放在 Home 授权的任务工作树；应根据任务执行收据打开对应目录，而不是把原始工作区当作当前执行目录。历史受管 Worker 会话继续通过只读诊断查看。人工接管本身不授予新的执行器权限。

## 后端对账与执行诊断（owner）

创建助手用量待核对时，owner 可先读取本机 Host 的 Builder 状态接口 `GET /api/kode/builder/close?operation_id=<operation_id>`。该只读接口要求 owner 身份，并按当前 Home/Builder operation scope 查询状态；它显示 operation、必要的未决 official call 引用及 accounting/reservation 投影。`frozen/held` 只描述该 reservation，不代表整个团队预算冻结。不得将读取失败、权限错误或网络错误解释为确定的缺计量状态。

Builder 明确报账入口为 `POST /api/kode/builder/accounting`，只接受显式内部计价确认。对于 Home 确认的 official usage unresolved，Host 返回结构化 `waiting_accounting / needs_reconciliation`；此状态表示没有完成结算，不能通过反复重试同一请求、手填 token 或追加预算解决。当前没有由 owner 伪造计量的补账 API，也不会自动退款或重放模型调用。

WorkRun 的 owner 可读取 `GET /api/kode/work-run/execution?run_id=<run_id>&team_id=<team_id>`。Host 会按精确 run/team/Home scope 读取 Home 的只读计量观察，并在确有当前未决用量时返回 `state: waiting_accounting`、`reason: usage_reconciliation_required`、必要的 `call_id/operation/attempt` 与该 operation reservation 的真实 held/charged/finalized 字段；不会返回 session 或 raw payload。非 owner、team 不匹配、权限拒绝或网络错误不能当成确定缺计量。对应的 Coordinator `kode_coordinator_workflow_status` 读取会包含 `execution_accounting`；持久 inbox 更新也会带相同 waiting reason 交给所属 Coordinator。该状态明确禁止重试 begin/新模型调用，直到 trusted usage reconciliation 完成；当前不提供手填 usage、退款或自动重放路径。

WorkRun 的 owner 还可从 `GET /api/kode/work-run/trace?run_id=<run_id>&team_id=<team_id>&view=model_calls` 或 `view=model_events` 读取 Home 锚定且范围受限的调用/事件元数据，辅助进一步诊断。Home 原始 `GET /api/v1/messaging/work-runs/:id/accounting-status` 是 admin-only backend route，由 Host 使用管理身份读取，不作为普通 Superagent/浏览器直连入口。以上接口均为只读状态观察；它们不结算 usage，也不改变预算或执行权限。

## 理解额度和预算

“团队预算”是用户配置的内部限额，系统在执行前预留，结合记录的用量扣减并对账。它与供应商真实余额、速率窗口、观测消耗分别显示。内部 credits 不是供应商货币余额。

查看执行资源与额度时，注意来源、账户绑定、限制桶、观测时间、过期状态及接入状态。没有真实供应商观测时仍显示未知；只有明确允许且内部预算足够，才可能在团队预算约束下准入。已知供应商耗尽不能通过增加团队预算绕过。

共享账户的团队共用账户容量；共享预算不会为每个团队复制一份余额。等待资源或预算时，系统可使用已有授权候选或暂停。提高限额是用户配置动作，模型不能自行加钱或扩大授权。估算和待对账记录不会伪装成供应商已确认账单。

## 声明命令使用的共享资源

登记验证命令时，可在“独占资源标识”填写设备、服务或端口的共同标识，例如 `device.camera,port:3000`。同一 Home 管理范围内，跨团队、跨执行 Host 使用同一物理资源的受管命令须使用相同标识；彼此独立的设备或主机本地端口应使用不同标识。系统不会解析任意脚本来猜测资源依赖。最多16项，不能重复或包含路径。

预览时检查“独占共享资源”，确认后资源声明与命令版本、内容哈希一起固定。创建助手读取已登记命令引用时，流程项目绑定应保留这份声明；少报或改名会被准入拒绝。修改声明需要登记新版本并重新核对相关配置。

工作使用资源前，Home 原子检查占用，Host 再持有实际内核锁。繁忙时原任务等待；停止请求或超时不等于可抢占，确认执行停止后才能释放。它是受管命令之间的协作排他，不会阻止未接入的手工程序访问设备，也不替代操作系统沙箱。

## 保存草稿和恢复导航

未发送内容、关联原任务和阅读位置按 Home 与联系人保存在浏览器 IndexedDB 中。界面显示“草稿已保存”后，可关闭并重新打开浏览器恢复。模式和原联系人也会恢复，包括首屏目录之外的联系人。

保存失败时，当前输入继续保留在页面中，可以重试保存。另一页面更新同一草稿时，界面提示冲突，选择“以当前草稿覆盖已保存版本”才会覆盖已有记录。发送记录关联具体草稿版本，重启恢复会核对该版本的接收回执。

## 整理联系人

打开对话上方的“团队管理”，可置顶、取消置顶、归档或移出归档。联系人按置顶、需要决定或处理的事项、未读和最近沟通排序。侧边栏的“已归档联系人”可查看和恢复归档记录。

归档设置保存在 Home。对话与任务继续保留。有在途任务或归档后的新消息时，联系人继续出现在主列表。“需要你确认”“等待资源”“停止待确认”来自 Hub 的任务状态。设置结果未确认时使用“恢复原联系人设置请求”，系统会查询原收据并保留原操作身份。

## 处理等待、异常和不确定回执

| 界面状态 | 处理方式 |
|---|---|
| 等待预算或资源 | 查看具体资源与预算记录，解决缺口后观察原任务恢复，不要为绕过限制重复建任务。 |
| 需要你的信息或决定 | 在所属团队中答复；结构化授权、验收、豁免等须使用对应确认入口。 |
| 执行端推进暂停 | 查看执行观测及 Hub 任务记录；满足条件时可审阅并“重新检查执行条件”。这只是请求检查原任务，不会替代停止、权限或证据门禁。 |
| 原请求结果尚未确认 | 使用“恢复原……请求”，保留原请求身份。不要清空本地记录来新发同一副作用。 |
| 原检查请求未提交且任务版本已改变 | 原请求保留为未生效记录。刷新当前任务，按当前状态处理，不能把它当成恢复成功。 |
| 已请求取消，尚未确认停止 | 继续等待或排查原执行端。取消请求不等于进程已停止；缺少停止证明时不会冒充已取消。 |
| 证据缺失或归档未完成 | 查看缺失项及来源。不能用聊天中的成功声明补齐证据。 |

创建助手若收到无法核验的用量，会显示“本次搭建用量待核对”，分别列出已发生的内部扣减和本次创建预留仍持有的金额；预留为零时如实显示零。此时尚未完成对账，不会宣称预算已经释放，也不会继续重复提交同一条必败的结束请求。后端保留缺计量调用和预留记录，增加预算不能补齐缺失的可信计量。当前没有允许手填 token 或绕过门禁的补账入口。

Home Hub 是团队状态的唯一权威。远端 Worker 通过受限路由报告回来；远端断线时，本地页面或执行端观察不能自行改写最终任务状态。

## 检索和导出协作档案

在任务“工作过程”中打开“查看完整追溯”。可按类型和关键词检索任务、分配、工具与权限事件、模型调用、内部通信、投递收据、关联请求、归档引用及共享团队历史。

记录按类型和游标组织。搜索到空页但仍有“继续搜索”，表示后面还有尚未扫描的记录。任务已有新版本时，先刷新任务详情和追溯；旧读取范围不会悄悄变成新版本的完整档案。

“导出追溯记录”导出全部类型，与当前搜索过滤无关。超过大小或数量上限时分成多个 JSON 文件，继续选择“继续导出下一部分”，保留同一次导出的所有部分，直到界面说明读取范围的记录已齐全。一个中间部分不代表完整导出。

导出的边界：

- Home 档案和已完成的产物、验证归档没有自动到期清理；目前未提供所有工作档案的主动删除功能。
- 工具输入与返回值保存内容哈希、字节数和会话调用关联，不把原始参数或返回内容复制到审计账本。原文依赖执行会话历史；远端会话离线时不承诺这些原文可读。
- 必要交付产物和验证日志有独立的 Home 归档。追溯 JSON 包含归档引用及可用状态，不包含这些归档的全部原始字节。
- 共享 Coordinator 操作或团队历史明确标注共享范围；其中的总用量不会被冒充为本任务独占用量。
- 提示词凭据表示 Host 记录的实际准备输入版本与哈希，不是供应商内部解释方式的证明。旧记录缺少凭据时继续显示缺失，不按当前代码补造。
- 导出隐藏凭证、命令环境和参数等敏感字段。它是读取和核对入口，不重执行历史操作。

## 已验证范围与后续验收

隔离测试覆盖真实 Hub、官方运行时、文件、进程和完整桌面浏览器。最新 Node 全量已完成：1176 项中 1169 通过、0 失败、7 跳过；Rust 最近检查 977 通过、7 忽略，GUI 0 错误、2 警告。P5.10 非视觉性能专项 29 项通过，包含真实 Chrome 的 5000 条变量高度历史、1000 条突发消息与重新挂载恢复。跳过项不算通过。

真实免费 hy4 最新完整案例已通过：创建助手 24 次、生成团队 33 次，共 57 次决策，均有可信用量和进程停止证据；三阶段、精确归档、独立任务工作树、原始 dirty 字节保留、自然关闭/预算归零、Hub 重启后同一团队再次响应和释放通过。498 个源/支持/验收文件及 3402 个运行依赖前后无差异，重启二进制一致。这是独立完整案例，不追溯改写此前失败或缺最终结算断言的历史 run。
