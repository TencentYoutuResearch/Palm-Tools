# Resume Flow Bug Investigation - Full Analysis

## Overview
The bug: "resume" in the GUI doesn't sync tab state. When a user selects a previous session to resume, the tab doesn't properly reflect the resumed session's metadata (model, title, tokens, session_id).

## THE BUG: Where State Sync Breaks

### Root Cause Analysis

The resume flow has **multiple potential failure points**:

#### Issue #1: jsonl Tail May Not Find Historical File

In `bridge/semantic.rs::spawn()`:
```rust
let path = match kode_core::session::jsonl_tail::resolve_session_path(
  backend,
  &cwd,
  &session_id,
) {
  Some(p) => p,  // Success: found old .jsonl file
  None => {
    // FALLBACK: file not found, use cwd path
    match backend.session_path(&cwd, &session_id) {
      Some(p) => p,
      None => {
        tracing::debug!(...);
        return;  // <-- EXITS WITHOUT STARTING TAIL
      }
    }
  }
};
```

If the old session's `.jsonl` file is deleted or in wrong location, **semantic tail never starts** → no `JsonlMeta` events → no metadata sync.

#### Issue #2: jsonl Tail Doesn't Emit Initial State

The jsonl tail only emits events as it **reads new lines** from the file. On resume:
- File already exists with historical data
- Tail seeks to start (or end?)
- May parse old entries but doesn't necessarily emit them

Critically: **What if tail seeks to END of file?** Then no historical metadata is read!

#### Issue #3: Race Condition

Timeline of resume:
1. `spawn_session` returns immediately with `SpawnedSession`
2. Frontend creates tab (model/title from initial spawn, likely defaults)
3. Child process loads `.jsonl` and writes resume metadata
4. jsonl tail starts and begins reading
5. First new metadata line is parsed → `CoreEvent::JsonlMeta` emitted
6. Frontend receives `session-meta` event → updates tab

**PROBLEM**: Steps 2-5 are async. If frontend renders tab before step 5 completes, user sees stale data momentarily. But more importantly, **if the metadata is never emitted, tab never updates**.

#### Issue #4: cwd Override on Resume

When resuming with a different cwd:
- Tauri command gets `cwd` parameter
- `resolve_session_cwd()` computes final path
- This path is used to **find the .jsonl file**
- But original session's .jsonl is at **original cwd location**

Example:
- Original: `cwd=/project/A`, `session_id=abc-123`
- jsonl file: `~/.codebuddy/projects/project-a/abc-123.jsonl`
- Resume with: `cwd=/project/B`, same `session_id=abc-123`
- Tries to find: `~/.codebuddy/projects/project-b/abc-123.jsonl`
- **File not found!** → Fallback path creation → No historical metadata read

## Missing Synchronization Points

### What Should Happen (Expected)

1. User clicks "Resume: Model X (50k tokens)"
2. Frontend spawns with `resumeSessionId=abc-123`
3. Backend:
   - Starts codebuddy with `--resume abc-123`
   - jsonl tail finds `abc-123.jsonl`
   - Reads historical entries (model, title, token count)
   - **IMMEDIATELY emits `CoreEvent::JsonlMeta`** with historical data
4. Frontend receives `session-meta` event
5. Tab updates to show "Model X (50k tokens)" instantly

### What Probably Happens (Actual)

1. User clicks "Resume: Model X (50k tokens)"
2. Frontend spawns with `resumeSessionId=abc-123`
3. Backend:
   - Starts codebuddy with `--resume abc-123`
   - `spawn()` returns before jsonl tail processes anything
   - Frontend tab shows default/empty model/title/tokens
4. jsonl tail task starts (microseconds later?)
5. jsonl tail seeks to... where? End of file?
6. Waits for new data (child process hasn't written yet)
7. Meanwhile, frontend has already rendered empty tab
8. Child process loads history, starts interactive session
9. First new jsonl entry triggers metadata update
10. Tab updates, but metadata is from **new interaction**, not resumed state

## Verification Points

### To Diagnose the Bug

Check in Rust:

1. **Does jsonl tail resolve the resumed session file correctly?**
   - Add debug logging to `bridge/semantic.rs::spawn()`
   - Verify file path matches where `.jsonl` actually lives

2. **Does jsonl tail seek to correct position?**
   - Check if `run()` function in `semantic.rs` reads from file start or end
   - Should read full file on first run to emit all historical metadata

3. **Are historical metadata events being emitted?**
   - Add logging in `spawn_event_router` for `CoreEvent::JsonlMeta`
   - Check if model/title/tokens are present

4. **Are events reaching frontend?**
   - Check browser console for `[session-meta]` logs
   - Verify `onSessionMeta` handler is called with historical data

Check in Frontend:

5. **Does tab update after `session-meta` event?**
   - Check React DevTools / Svelte store state
   - Verify `tabs` store is updated with model/title/tokens

### Hypothesis

Most likely: **jsonl tail doesn't read or emit historical metadata on resume**

The fix should:
- On resume, immediately parse entire .jsonl file (not just new lines)
- Emit `CoreEvent::JsonlMeta` with latest historical state before PTY starts
- Ensure frontend receives event before tab renders initial state
