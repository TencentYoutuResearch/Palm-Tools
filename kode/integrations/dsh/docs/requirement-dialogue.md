# 需求对话与后续业务验收

## 对话原则

默认从目标、使用场景和可观察的验收效果谈需求，不让用户把问题翻译成“在工作区创建某文件”或工具调用步骤。用户明确指定的路径、接口、参数、原文、范围和禁止事项必须保留；自然表达不意味着屏蔽技术细节，也不意味着删掉约束。

Coordinator 保留原始请求及全部显式约束，再映射到已配置的 workflow 输入。补充概述不能替代原文。Worker 根据原始 mandate 和已冻结的执行上下文实现、审查、验证；对外解释实际结果和待确认事项，不把创建了文件、调用了工具或接收了任务说成功能已经实现。需要交付位置、技术诊断或用户要求时，仍应提供准确路径和技术名称。

频道首页只展示例句，不自动填草稿、不自动发消息、不授予执行权限。既有消息、原始截图和证据记录不为改善措辞而重写。
